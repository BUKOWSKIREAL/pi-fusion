# Pi Fusion

[English](README.md) | 简体中文

Pi Fusion 是一个 [Pi](https://pi.dev) 扩展，让两个模型在同一个项目里分工协作：

- **主模型（lead）**：与你沟通、确定方案、分配任务，并检查最终结果。它就是你当前使用的 Pi 模型。
- **协作模型（sidekick）**：接收主模型交给它的任务，完成具体实现、查找和验证。

协作模型会保留自己的对话记录。下一次交接时，主模型可以接着安排工作，无需从头解释。每个主会话只有一个协作模型；任务执行期间，也可以继续向它补充要求。

这是一个独立扩展，与 Cognition / Devin 没有隶属或官方合作关系。

## 看一遍协作流程

选模型 → 交任务 → 后台执行 → 检查结果 → 继续协作。

## 快速开始

### 1. 准备环境

- Node.js `>=22.19.0`
- Pi（已在 Pi 1.0.3 上测试）
- 已在 Pi 中配置好一个可用的协作模型，包括对应的服务商凭据

### 2. 安装扩展

已发布到 npm：[`pi-local-fusion`](https://www.npmjs.com/package/pi-local-fusion)。在终端运行：

```bash
pi install npm:pi-local-fusion
```

包已包含供 [Pi 包广场](https://pi.dev/packages) 发现的 `pi-package` 关键词。新版本发布后，广场索引可能需要一些时间更新。

<details>
<summary>从 GitHub 或本地目录安装</summary>

从 GitHub 安装：

```bash
pi install git:github.com/BUKOWSKIREAL/pi-fusion
```

如果已经下载了源码，在其上一级目录运行：

```bash
pi install ./pi-fusion
```

</details>

### 3. 选择协作模型

回到 Pi，依次输入：

```text
/reload
/fusion
```

第一次运行 `/fusion` 会直接打开模型选择器。选择一个已配置凭据的模型后，Fusion 就会启用，并记住这个默认选择。

**主模型不会因此改变。** Pi 自带的 `/model` 仍用于切换主模型；`/fusion-model` 用于选择协作模型。协作模型需要一个具体模型，因此选择器不显示虚拟模型路由器。

### 4. 像平时一样提出任务

不需要手动调用协作工具。直接向主模型说明需求，例如：

```text
给报表页增加 CSV 导出功能。先确定方案，再把实现和相关测试交给协作模型。
检查完整代码改动和测试结果后，再向我汇报。
```

主模型会判断哪些工作适合交出去，并在拿到结果后进行检查。

## 日常使用

后续输入 `/fusion`，会打开简洁的设置菜单：选择协作模型、开启或关闭 Fusion、查看详情。

| 命令 | 用途 |
| --- | --- |
| `/fusion` | 打开设置；首次使用时直接选择模型 |
| `/fusion-model` | 选择或更换协作模型 |
| `/fusion status` | 查看当前模型、限制、会话文件和用量 |
| `/fusion stop` | 停止当前任务，保留协作模型的上下文和已修改的文件 |
| `/fusion off` | 停止当前任务并关闭 Fusion；下次启动仍保持关闭 |
| `/fusion on` | 启用 Fusion；没有默认模型时先打开选择器 |
| `/fusion help` | 查看全部命令 |

更换协作模型或调整工作设置前，先用 `/fusion stop` 停止正在执行的任务。

## 协作时需要知道的事

**两边共享项目文件，但不共享完整对话。** 协作模型只能看到主模型交给它的说明、自己的历史记录，以及 Pi 发现的工作区指令（如 `AGENTS` 文件）。你补充的要求，需要由主模型转交。因此，主模型应避免同时修改协作模型正在处理的文件。

**等待结束，不一定代表任务结束。** 默认交接最多等待 60 秒，超时后任务仍在后台继续。也可以从一开始就安排后台执行，让主模型继续处理其他工作。完成后主模型会收到通知，并读取结果。再次交接会向同一个协作模型补充要求，不会另开一个。

**停止任务不会撤销文件修改。** 在等待期间按 Esc，或退出、重载、切换会话、在会话树中导航，都会停止当前任务；协作模型的上下文会保留。切换会话分支也不会回滚工作区文件。

**协作模型只加载 Pi 的内置工具。** 默认 `coding` 模式可读写文件并执行 Bash；`readonly` 模式只提供读取和搜索工具。它不会自动继承主模型的扩展、MCP、技能或自定义工具。每次 Bash 调用都是独立的 shell；Bash 以你的系统权限运行，并非沙箱。

**用量在领取结果时计入。** 主模型通过阻塞交接拿到结果，或调用 `read_sidekick` 读取结果时，协作模型的 token 和费用才计入主会话。后台完成通知本身不计费；反复读取同一份结果也不会重复计入。因此，结果尚未领取时，`/cost` 可能还没显示这部分用量。

## 进阶命令

### 模型与上下文

| 命令 | 用途 |
| --- | --- |
| `/fusion model provider/model-id` | 手动设置默认协作模型，并启用 Fusion |
| `/fusion assign provider/model-id` | 只为当前会话分支指定协作模型，保留上下文，不修改全局默认模型 |
| `/fusion compact` | 压缩空闲协作模型的上下文，逐字保留已送达的任务交接文本 |
| `/fusion reset` | 停止任务并解除当前保存的上下文关联；下次交接从新对话开始 |

`provider/model-id` 应使用 Pi 模型列表中的完整标识。更换模型会保留空闲协作会话；`assign` 不改变其角色和工具集。

压缩会请求模型生成摘要，因此会产生用量。若需要保留的交接文本和剩余上下文超出预计容量，压缩会报错停止。摘要请求即使失败或取消，只要返回了用量，也会计入 Fusion 用量。当前压缩使用 Pi 的调度机制和本地交接文本保留适配器，并未复现 Devin 的异步压缩调度器。

**`reset` 会让协作模型失去当前上下文，请在确实需要重新开始时使用。** 它保留项目文件、全局默认设置和磁盘上的旧会话文件，便于之后排查。

### 工作限制与提醒

| 命令 | 可选值与默认值 |
| --- | --- |
| `/fusion thinking <level>` | `off`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`；默认 `medium`，实际受模型能力限制 |
| `/fusion tools coding` / `readonly` | 工具集；默认 `coding` |
| `/fusion timeout <minutes>` | 每次交接的总时限，1–240 分钟；默认 15 分钟 |
| `/fusion turns <count>` | 每次交接的轮数上限，1–1000；默认 80 |
| `/fusion reminders on` / `off` | 首条消息和主模型首次直接编辑时的一次性提醒；默认开启 |
| `/fusion routing jev` / `off` | Jev 分工建议；默认关闭 |

## 设置保存在哪里

全局默认设置保存在：

```text
~/.pi/agent/fusion/config.json
```

协作模型的会话记录保存在：

```text
~/.pi/agent/fusion/sessions/
```

如果设置了 `PI_CODING_AGENT_DIR`，这两个位置会随之改变。`/fusion status` 会显示实际路径。要查看某个协作会话，可以运行 `pi --session <会话文件路径>`。

- **新会话使用全局默认设置。** 已有 Fusion 状态的会话分支优先恢复自己的设置。
- 开关、默认模型、思考等级、工具集、时限、轮数、提醒和路由设置会写入默认配置。`stop`、`reset`、`status`、重载和退出不会修改它。
- `assign` 指定的模型、协作历史、最近结果、Jev 建议和用量都保存在会话分支中，不写入全局默认配置。
- 凭据仍由 Pi 的服务商配置或环境变量管理，Fusion 不保存凭据。

<details>
<summary>旧会话迁移与环境变量</summary>

重载旧会话时，如果它已经配置了协作模型，而且全局默认配置文件尚不存在，Fusion 会将其设置写入默认配置一次。已有配置文件不会因此被覆盖。

配置文件无法读取或内容无效时，Pi 会提示，并回退到内置默认值。

`PI_FUSION_MODEL` 仅在尚未设置协作模型时预填模型，不会自行启用 Fusion。

</details>

## 可选：Jev 分工建议

默认无需启用 Jev。主模型本身就会决定如何分工。

若希望额外获得 TypeSafe 的分类建议，先在环境变量中配置 `TYPESAFE_API_KEY`，再运行：

```text
/fusion routing jev
```

Jev 只提供建议。主模型仍负责决定是否交接、编写任务说明和检查结果。

<details>
<summary>发送的数据、判断规则和用量</summary>

- 每条新用户请求最多触发一次 TypeSafe Choice 调用。只发送当前请求（最多 8000 字符）和固定的角色说明，不附加代码文件、完整对话或凭据；如果你把这些内容写进当前请求，它们也会随请求发送。
- 分类结果为 `lead`、`sidekick` 或 `uncertain`。只有结果为 `sidekick`、置信度至少 0.8，且 sidekick 概率至少 0.85 时，才建议交给协作模型。
- 其他情况，包括缺少密钥、输入过长或调用出错，都回退到主模型。每次调用最多等待 4 秒，不重试。
- 这些阈值是经验规则，并非经过校准的准确率保证。
- Jev 用量单独显示在 `/fusion status` 中，不计入 `/cost`。

[evaluation/jev-routing.json](evaluation/jev-routing.json) 记录了 10 个合成案例的集成冒烟测试，不能据此判断实际分工质量或成本节省。

</details>

## 状态与排查

启用后，Pi 状态栏会显示 `Fusion · <状态>`。编辑区下方还会并排显示主模型和协作模型，并突出显示正在生成输出的一方。

| 情况 | 如何处理 |
| --- | --- |
| 显示 `Fusion · failed` | 表示最近一次交接失败，常见原因是达到轮数上限或服务商报错。让主模型读取结果，或打开协作会话文件查看详情 |
| 读取结果或 `/reload` 后仍显示失败 | 这是最近一次任务的状态，会在下一次交接时更新 |
| 需要停止当前工作 | 使用 `/fusion stop`，保留上下文供下次继续 |
| 确实需要从新对话开始 | 使用 `/fusion reset`；它不会撤销文件修改 |
| 命令或工具名称冲突 | 若其他扩展也注册了 `/fusion` 或 `sidekick`，停用其中一个 |
